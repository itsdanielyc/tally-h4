## Rulings

- Slice 0. Ruling: Treat the embedded skill templates as inventory inputs only — the root contains no app code — cost if wrong: scaffold would halt on a file conflict.
- Slice 0. Ruling: Use in-repository Keel, authorized PRs, and hosted workflows for all platform proof — this is an unattended solo run — cost if wrong: CI or repository settings can be restored and rerun.
- Slice 0. Ruling: Use `com.example.tally` and confine the scaffold rename pass to app files — no publisher identifier was provided and the embedded skills are inputs — cost if wrong: a future bundle-ID change needs a user-data migration.
- Slice 0. Ruling: Dispatch snapshots from a working branch and open the PR with `gh` — keeps the repository's Actions bot approval permissions unchanged and starts CI for the captured commit — cost if wrong: a manual PR replaces the template's bot PR.
- Slice 0. Ruling: Accept the isolated hosted macOS arm64 real-shell rerun alongside the normal CI run — the normal macOS real-shell job stayed queued and the rerun differs only in workflow scheduling — cost if wrong: the normal job must be rerun before treating a runner-specific defect as resolved.
- Slice 1. Ruling: Use the system currency when supported and allow changing it while the ledger and budgets are empty — changing the unit on existing amounts would misrepresent them — cost if wrong: a separate currency migration would be needed.
- Slice 1. Ruling: Prepare transaction recording on an isolated branch while GitHub queues the scaffold's macOS real-shell job — the other scaffold lanes already have hosted proof — cost if wrong: the branch must wait or rebase before merging if the scaffold job finds a defect.
- Slice 1. Ruling: Retire the proven template greeting with its demo fixtures when the transaction UI replaces it — the product's replacement checks exercise the same mock, visual, preload, and real-shell paths — cost if wrong: a lost harness assertion must be restored in the new journey.
- Slice 1. Ruling: Pin the hosted Apple silicon jobs to `macos-26` — the isolated real-shell job obtained a runner there and confirmed arm64 — cost if wrong: moving to a different macOS image requires fresh pixel baselines.
- Slice 2. Ruling: Check duplicates against the committed ledger at confirmation and preserve identical rows within the new batch — an empty ledger must reproduce separate identical transactions on round trip — cost if wrong: duplicate rows already present in a bank export are also preserved in its first import.
- Slice 2. Ruling: Read UTF-8 and BOM-marked UTF-16 up to 32 MB — covers typical bank statements while bounding work in the desktop app — cost if wrong: larger or differently encoded statements need to be split or saved in a supported encoding.
- Slice 6 review. Ruling: Limit one CSV import or export to 25,000 data rows and display rejection pages of 50 — a short malformed file could otherwise allocate millions of records — cost if wrong: very large ledgers must be imported in batches or exported with a narrower filter.
- Slice 3. Ruling: Match payee substrings case-insensitively in creation order and apply rules only when the transaction has no category — preserves explicit choices and gives overlapping rules predictable precedence — cost if wrong: the user must edit or recreate the rules to change precedence.
- Slice 4. Ruling: Measure budgets against spending alone and keep one recurring monthly limit per category — income is shown separately and the slice requests a monthly limit — cost if wrong: month-specific budgets would require a later schema change.
- Slice 4. Ruling: Add both limits when categories merge and remove a limit when its category is deleted — the surviving amount follows the surviving transactions — cost if wrong: the recurring destination budget can be edited after the merge.
- Slice 5. Ruling: Use a single session undo slot, cleared by the next effective ledger change — matches immediate one-shot recovery — cost if wrong: use cases requiring persisted history need a later design.
- Slice 5. Ruling: Carry currency, category and note in Tally CSVs, with reversible protection for formula-like text — exact round trips need those details — cost if wrong: readers of the raw CSV may see a leading apostrophe on protected cells.
- Slice 6. Ruling: Use unsigned packages per ADR 001 and run the release workflow by dispatch — proves the same bundle and smoke jobs before tagging — cost if wrong: signed distribution and tag publication need a separate run.
- Slice 6. Ruling: Keep the seeded product version at 0.1.0 and check both package manifests — SLICES.md specifies the release number — cost if wrong: the manifests and changelog must change together.
- Slice 6. Ruling: Use the standard `macos-latest` Apple silicon runner for installer proof — it previously built and launched the DMG, while `macos-26` jobs repeatedly waited without assignment — cost if wrong: macOS checks must run again on another Apple silicon image.
- Pipeline proof. Ruling: Use one isolated macOS Apple silicon workflow to verify the exact source commits for slices 1–5, alongside Linux and Windows jobs on those same commits — parallel macOS lanes repeatedly stayed queued — cost if wrong: platform-specific differences must be checked again in the final CI run.
